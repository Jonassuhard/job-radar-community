# Securite

## Signaler une vulnerabilite

Utilise un GitHub Security Advisory prive pour signaler une vulnerabilite. Ne
cree pas d'Issue publique avant accord des mainteneurs. Le signalement doit
decrire les versions concernees, les etapes de reproduction minimales et
l'impact, sans secret ni donnee personnelle.

N'inclus jamais de CV, cookies, jetons, mots de passe, cles API, sessions de
navigateur ou bases SQLite. Revoque immediatement tout secret accidentellement
expose avant de le signaler.

## Perimetre

Sont notamment pertinents: l'ecoute locale de l'API, les jetons de session, les
ecritures de configuration, les imports, les dependances et les gardes contre
la publication de donnees privees. Les demandes d'auto-candidature, de crawler
LinkedIn, Indeed ou Welcome to the Jungle, ou de contournement de CAPTCHA sont
hors perimetre.

## Traitement

Le projet est maintenu en best effort. Les mainteneurs accusent reception et
coordonnent une correction quand cela est possible; aucun delai de reponse ou
de correction n'est garanti. La politique de version est indiquee dans
[SUPPORT.md](SUPPORT.md).
